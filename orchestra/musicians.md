# Erste Besetzung: Rollen und Kandidaten

Diese Liste bewahrt die vorgeschlagene Besetzung. Sie ist **vorläufig**: Instrumente sind Rollenmetaphern, keine technischen Aussagen über die Anbieter. „API ungeprüft“ bedeutet, dass der Zugang und die Eignung für ManualAI noch nicht bestätigt sind.

| Instrument / Rolle | Vorgeschlagener Kandidat | Vorläufige Einordnung | Status |
| --- | --- | --- | --- |
| Cello | Opera Browser | Vom Projektinhaber wegen einer Browser-/Krypto-Earn-Funktion vorgeschlagen. Browser oder Reward-Funktion wäre Infrastruktur, nicht von sich aus eine Modellstimme. | Produkt und offizielle API bzw. Reward-Bedingungen verifizieren |
| Gesang | ManualAI / Orpheus | Eigene künftige Stimme des Projekts. | Noch nicht bereit; API und Fähigkeiten offen |
| Percussion | Grok | Vorgeschlagene kreative Modellstimme. | Aktuelles Modell, Entwicklerzugang und Eignung prüfen |
| Klavier | Claude | Vorgeschlagene kreative Modellstimme. | Aktuelles Modell, Entwicklerzugang und Eignung prüfen |
| Saxophon | ChatGPT | Vorgeschlagene kreative Modellstimme. | ChatGPT-Abonnement und API-Zugang getrennt prüfen |
| Gitarre | Pi Network | Vorgeschlagener Kandidat; der genaue Dienst ist unklar. Pi Network, Pi-AI-Produkte und andere „Pi“-Dienste nicht gleichsetzen. | Produktidentität zuerst klären |
| Heckler im Publikum | DeepSeek | Vorgeschlagene Gegenstimme für Einwände, Brüche oder Kritik. | API, Nutzungsbedingungen und Datenverarbeitung prüfen |

| Alternative Stimmen / Werkzeuge | Copilot | Zusatzkandidat; genaue Produktlinie (z. B. Microsoft Copilot oder GitHub Copilot) klären. | Produkt und Entwicklerzugang konkretisieren |
| Musik-Katalog / Wiedergabe | Spotify „Ben“ API | Als mögliche Audio-/Playback-Schicht vorgeschlagen, nicht als Sprachmodell. Der genaue „Ben“-Bezug ist offen. | API, Kontoberechtigung, Wiedergabegrenzen und Einsatz klären |

## Auswahlregel

Ein Kandidat wird erst in die **aktive Besetzung** aufgenommen, wenn ManualAI ihn über einen unterstützten API-Zugang aufrufen darf, die Kosten und Limits bekannt sind und die Nutzungsbedingungen den geplanten Austausch der Modellbeiträge erlauben. Bis dahin bleibt er ein Vorschlag.

## Zu prüfende Besetzungsfragen

1. Welche Stimmen bringen wirklich unterschiedliche kreative Perspektiven statt nur verschiedene Markennamen?
2. Welche Kandidaten dürfen direkt miteinander erzeugte Texte austauschen?
3. Welche Stimmen sollen Motive erzeugen, welche kritisieren, und welche komponieren das Endstück?
4. Braucht das erste Stück Text, Sprache, Musik oder mehrere getrennte Render-Schritte?
5. Welche Kandidaten sind APIs, welche nur Benutzeroberflächen und welche sind Infrastruktur?
